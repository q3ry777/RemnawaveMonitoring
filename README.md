# Remnawave Monitor

Приложение для Windows, которое следит за панелью [Remnawave](https://github.com/remnawave): пользователями, нодами, оплатой серверов и версиями. Живёт в системном трее, показывает проблемы красной иконкой и уведомлениями, ведёт журнал событий и сам обновляется из релизов этого репозитория.

Отдельно в репозитории есть **Telegram-бот** (`bot/`) — он ставится Docker-контейнером на сервер с панелью, работает круглосуточно и присылает тревоги и сводки в Telegram независимо от компьютера.

Стек: C#, .NET 8, WPF (программа), .NET 8 + Docker (бот). Настройки программы хранятся локально, токены — в зашифрованном виде.

## Требования

- Windows 10 или 11.
- [.NET 8 Desktop Runtime](https://dotnet.microsoft.com/download/dotnet/8.0), если используется сборка из релизов (она не содержит среду выполнения внутри).
- Доступ к панели Remnawave и её API-токен. Достаточно токена **только на чтение**.

## Установка и первый запуск

1. Скачайте `RemnawaveMonitor-win-x64.zip` из последнего релиза и распакуйте `RemnawaveMonitor.exe` в любую постоянную папку (не в «Загрузки»).
2. Запустите программу и откройте **«настройки»**.
3. Укажите адрес панели и API-токен, при необходимости измените остальные параметры и нажмите **«сохранить»**.
4. Для автоматических обновлений программы заполните раздел «Обновления программы» (см. [ниже](#обновление-программы)).

Запуск второй копии невозможен: она лишь покажет окно уже работающей. При закрытии крестиком окно прячется в трей; полный выход — пункт «Выход» в меню иконки.

## Что показывает программа

Главное окно состоит из трёх вкладок. Сверху — шапка с названием, версией программы, плашками о новых версиях и кнопками «журнал», «тема», «настройки», «обновить». Под ней — счётчики «онлайн» и «ноды N/M». Данные обновляются автоматически (по умолчанию каждые 30 секунд).

### Пользователи

Список всех пользователей панели.

- Имя, статус (ACTIVE и др.), трафик, последняя нода с флагом страны, время последней активности.
- Если у пользователя есть лимит трафика, показывается «использовано / лимит» и полоска расхода: жёлтая от 80%, красная от 95%.
- Рядом с именем появляется метка срока подписки: «ещё N д» за 7 дней, красная за 3 дня, «истёк» после окончания.
- «Онлайн» — пользователь, чья последняя активность была не раньше заданного окна (по умолчанию 300 секунд). Онлайн-пользователи отмечены зелёной точкой со свечением.
- **Поиск** по имени.
- **Сортировка** по клику на заголовок столбца: имя, статус, трафик, нода, активность (повторный клик меняет направление).
- **Фильтры:** «только онлайн» и «проблемные» (не ACTIVE, лимит близок, подписка скоро истекает).
- **IP активного подключения** под последней нодой (`95.24.x.x`, при нескольких адресах — `+N`, все адреса с нодой и временем — при наведении). Берётся из панели раз в минуту, только с нод, на которых кто-то онлайн (панель 3.x: `/api/connections/by-node`, 2.x: `/api/ip-control`). API-токену нужны права на чтение подключений (connections); если их нет, внизу окна будет подсказка.
- **Устройства (УСТР.)** — сколько устройств (HWID) зарегистрировано у пользователя и лимит: `2/3`; жёлтым — лимит исчерпан, при наведении — подробно. Обновляется раз в 5 минут одним списком всех устройств панели (`/api/hwid/devices`). Если в столбце «—», у панели не включён учёт устройств или у API-токена нет прав на их чтение. Столбец сортируется.
- **Карточка пользователя** — двойной клик по строке или «открыть карточку» в меню правой кнопки: срок подписки, трафик и лимит (с полоской), стратегия сброса, трафик за всё время, лимит устройств, первое подключение, описание; **трафик за 14 дней** столбиками (сегодня — зелёный, значение — при наведении) и по нодам; IP активных подключений (щелчок — скопировать); **устройства (HWID)**: модель, система, приложение, когда последний раз. Трафик и устройства запрашиваются у панели при открытии и по кнопке «обновить» (панель 3.x: `/api/bandwidth-stats/users/{id}`, `/api/hwid/devices/{id}`; 2.x: `/api/users/stats/usage/{uuid}/range`, `/api/hwid/devices/{uuid}`). Если раздел пустой с пометкой «нет данных» — у панели нет этих данных или у API-токена нет прав на их чтение.
- **Кто онлайн.** Пользователь онлайн, если его активность в панели (`onlineAt`) моложе окна из настроек **или** у него есть IP среди активных подключений нод за последние 5 минут. Поле `onlineAt` панель обновляет с задержкой и только при трафике, поэтому подключённый, но тихий клиент по нему одному выглядел бы офлайн. Время считается по часам панели (по заголовку `Date` её ответов), так что расхождение часов компьютера не мешает.
- Меню по правому клику: копировать имя, копировать IP, копировать ссылку подписки, открыть панель в браузере.
- При автообновлении положение прокрутки сохраняется.

### Ноды

Каждая нода — карточка из трёх строк.

1. Точка состояния, флаг, название, статус; трафик ноды («использовано / лимит», `∞` без лимита, полоска при наличии лимита); аптайм Xray; число пользователей онлайн.
2. Шкала **RAM** (данные панели; жёлтая от 75%, красная от 90%, при наведении — «занято / всего»), число ядер и load average, текущая скорость ↓ и ↑.
3. **Версии** ноды и Xray, устаревшая нода подсвечена: `node 3.4.0 → 3.4.1` (строка видна, если есть данные).

**Оплата сервера** из биллинга панели — плашка рядом с именем ноды: `оплата 10.11 · 30 д`; жёлтая за 7 дней, красная за 3 дня и при просрочке. При наведении — полный текст с провайдером.

Меню по правому клику: копировать имя, копировать адрес ноды, открыть панель.

### Прочее в интерфейсе

- **Тёмная и светлая тема.** Переключается кнопкой «тема» или в настройках; цвет системного заголовка окна подстраивается под тему.
- **Плашка «нет связи с панелью»**: если панель недоступна, программа показывает последние сохранённые данные с временем их получения.
- Положение, размер окна и развёрнутость на весь экран запоминаются (если монитор отключён — окно откроется по центру).
- Минимальная ширина окна — 960 пикселей.

## Иконка в трее и уведомления

**Цвет иконки**

- **Зелёная** — непрочитанных проблем нет.
- **Красная** — появилась новая проблема, которую вы ещё не отметили прочитанной.

Проблема считается прочитанной (иконка снова зеленеет), если вы:

- кликнули по уведомлению (откроется журнал событий);
- закрыли уведомление крестиком в течение нескольких секунд после показа;
- нажали «всё прочитано» в журнале или закрыли окно журнала;
- выбрали «Отметить прочитанным» в меню иконки.

Если проблема продолжается, а вы её уже отметили, иконка остаётся зелёной, но в подсказке видно ⚠, а в журнале событие числится как «идёт».

**Подсказка** при наведении: `онлайн 4 · ноды 6/6 · RAM до 49%`.

**Меню иконки:** Открыть, Журнал событий, Отметить прочитанным, Настройки, Выход. Двойной клик открывает главное окно.

**О чём приходят уведомления**

- нода отключилась (статус «В сети» сменился) и снова в сети;
- потеря связи с панелью — только если у самого компьютера есть интернет (после сна или при обрыве связи тревоги нет, в строке состояния — «нет интернета»);
- срок оплаты сервера (за 3 дня и при просрочке);
- пользователь израсходовал 95% лимита трафика или у него истекает подписка (за 3 дня и после окончания);
- вышли новые версии Remnawave (панель, нода) и самой программы;
- восстановление после проблемы.

Уведомления программы — только на этом компьютере (Windows и журнал). В Telegram пишет [бот на сервере](#telegram-бот-на-сервере); когда программа или компьютер выключены, от программы ничего не приходит.

**Вид уведомлений.** По умолчанию — уведомления Windows нового вида: остаются в центре уведомлений, у проблем есть кнопка «Журнал», у уведомлений о подписке пользователя — «Карточка». Отключается в настройках → «общие» (тогда — старые всплывающие у трея).

**Что нового.** После обновления программа один раз показывает список изменений; весь список — настройки → «обновления» → «что нового».

**Защита от ложных тревог.** О проблеме сообщается, только если она подтвердилась при двух проверках подряд. Проблемы, которые уже были в момент запуска программы, попадают в журнал как прочитанные и тревогу не поднимают.

## Отключение уведомлений по ноде

Правый клик по ноде на вкладке «Ноды» — пункты уведомлений. Каждый пункт включает или выключает свой вид уведомлений по этой ноде:

- отключение ноды (не в сети);
- оплата сервера.

Есть и пункт «отключить/включить все уведомления по ноде».

Отключённые проблемы по-прежнему записываются в журнал событий (с пометкой «уведомления отключены»), но не всплывают, не уходят в Telegram и не делают иконку красной. Рядом с именем ноды видно, что отключено (`🔕 из РФ, оплата`). Настройка сохраняется между запусками.

## Журнал событий

Окно открывается кнопкой «журнал» в шапке (на ней видно число непрочитанных) или из меню иконки.

- Каждая проблема — строка: время начала, объект, описание, состояние. Активные проблемы показывают «идёт N мин», решённые — «решено · N мин».
- Новые события подсвечены и помечены `NEW`.
- В верхней части — сводка: активно сейчас, новых, всего.
- Кнопки: «всё прочитано», «очистить решённые», «закрыть».
- Журнал хранится в файле и переживает перезапуск; хранятся последние 300 записей. Проблемы, которые были активны на момент закрытия программы, при следующем запуске помечаются завершёнными.

## Telegram-бот на сервере

Бот — отдельная программа (`bot/`), которая ставится Docker-контейнером **на сервер с панелью**, рядом с Remnawave, в её сеть `remnawave-network`. Работает круглосуточно и не зависит от компьютера. К панели обращается напрямую внутри Docker (`http://remnawave:3000`) — наружу ничего не открывается.

**Что присылает** (для каждого вида — своя галочка):

- нода не в сети и снова в сети (с длительностью простоя) — после двух проверок подряд (~1 мин);
- оплата сервера — за 3 дня и при просрочке;
- пользователь израсходовал 95% лимита трафика или у него истекает подписка;
- новые версии Remnawave (панель, ноды).

О недоступности самой панели бот не сообщает: если лёг сервер, бот лежит вместе с ним. Это заметит программа на ПК.

**Меню и команды** (кнопки под полем ввода и меню «/»):

| Команда | Что делает |
|---|---|
| `/status` | Сводка: онлайн, ноды, RAM, ближайшая оплата, активные проблемы |
| `/nodes` | Подробности по каждой ноде |
| `/users` | Кто сейчас онлайн, на какой ноде и с каких IP |
| `/problems` | Активные проблемы |
| `/version` | Версии панели, нод и бота |
| `/dnd` | Кнопка «🔕 Не беспокоить»: тишина до утра (время задаётся в настройках, по умолчанию 08:00), повторно — выключить; `/dnd 10:30` — до своего времени, `/dnd off` — выключить |

Тихие часы по расписанию (например, 23–08) задаются в настройках. В тишину тревоги не отправляются (видны в `/problems` и в журнале контейнера), ответы на команды приходят всегда. Командам админа бот отвечает только админским чатам. Состояние (открытые проблемы, «не беспокоить», отправленные тревоги) хранится в `/opt/remnawave-bot/data`, поэтому после перезапуска или обновления те же тревоги повторно не приходят.

**Вебхуки панели.** Если включены (галочка в настройках), команда установки вписывает в `/opt/remnawave/.env` `WEBHOOK_ENABLED=true`, `WEBHOOK_URL=http://remnawave-bot:8080/webhook` и `WEBHOOK_SECRET_HEADER` (копия файла — `.env.rw-bot-backup`) и перезапускает панель (~20 секунд). Если у панели уже есть свои вебхуки, адрес бота добавляется к ним через запятую, а бот берёт их секрет. Подпись каждого события проверяется (`X-Remnawave-Signature`, HMAC-SHA256). Что приходит сразу:

- нода не в сети / снова в сети (опрос остаётся запасным вариантом), нода добавлена, удалена, отключена или включена в панели;
- **события пользователей** (вид `users`): создан, удалён, перевыпущена подписка, отключён/включён, трафик закончился, подписка истекла, впервые подключился, новое устройство, торрент заблокирован, пользователь подключил бота;
- **события панели** (вид `panel`): вход в панель и неудачная попытка входа (логин и IP; пароль из события не пересылается), перезапуск панели, создан или удалён API-токен.

**Дополнительные админы.** В настройках — по строке на человека: Telegram ID и виды уведомлений через запятую (`nodes`, `limits`, `billing`, `updates`, `users`, `panel`; без списка — всё). Например `123456789 nodes,billing`. Им доступны те же команды на просмотр, у каждого своё «не беспокоить».

**Личный кабинет пользователей.** Если у пользователя в панели указан Telegram ID, он может написать боту: кнопка «👤 Мои подписки» показывает все его подписки по названиям (один ID может стоять у нескольких пользователей — например, у семьи), по нажатию — срок, трафик и остаток, устройства, последнее подключение, ссылку на подписку. Видны только подписки со своим Telegram ID. Незнакомому человеку бот отвечает, что подписок нет, и показывает его Telegram ID — чтобы передать админу. Если у тебя самого Telegram ID стоит у каких-то пользователей, кнопка «Мои подписки» есть и в твоём меню (`/my`).

**Напоминания пользователям.** Бот сам пишет пользователю: за N дней до окончания подписки (по умолчанию 3) и в последние сутки, когда подписка истекла, когда израсходовано N% трафика (по умолчанию 90) и когда трафик закончился. Подписка называется по имени; несколько напоминаний в один момент приходят одним сообщением. Каждое — один раз. Писать первым бот может только тем, кто хоть раз нажал `/start` (ограничение Telegram); сколько пользователей с Telegram ID и сколько из них подключили бота — в «Сводке». Пользователь отключает напоминания кнопкой «🔕 Не напоминать».

**Установка** (в программе: настройки → «telegram-бот»):

1. Создайте бота у [@BotFather](https://t.me/BotFather), вставьте токен, напишите боту сообщение и нажмите «привязать чат», затем «отправить тест».
2. Выберите, что присылать, тихие часы и время «не беспокоить».
3. Нажмите «скопировать команду установки» и выполните её на сервере с панелью под root. Команда создаёт `/opt/remnawave-bot` с `.env` (токены, права 600) и `docker-compose.yml`, скачивает образ `ghcr.io/q3ry777/remnawave-bot` и запускает контейнер. В `.env` подставляются API-токен панели из настроек программы и часовой пояс этого компьютера.
4. Бот пришлёт приветствие с кнопками.

Образ собирается в этом (приватном) репозитории, поэтому пакет `remnawave-bot` в GitHub Packages по умолчанию тоже приватный. Чтобы сервер мог его скачать без логина, один раз сделайте пакет публичным: GitHub → профиль → Packages → `remnawave-bot` → Package settings → Change visibility → Public. В образе только код бота, токенов в нём нет. Другой вариант — `docker login ghcr.io -u q3ry777` на сервере с токеном `read:packages`.

После изменения настроек — снова скопируйте и выполните команду (настройки перезапишутся, контейнер перезапустится).

**Автообновление.** Команда установки добавляет в cron задание: каждый день в 04:17 по времени сервера бот проверяет новую версию образа и, если она есть, перезапускается с ней (`crontab -l` — посмотреть, строка с пометкой `# remnawave-bot`). Отключить: `crontab -l | grep -v remnawave-bot | crontab -`.

**Команды на сервере:**

```
cd /opt/remnawave-bot && docker compose pull && docker compose up -d   # обновить бота
docker logs -f remnawave-bot                                           # журнал
nano /opt/remnawave-bot/.env && docker compose up -d                   # поменять настройки вручную
docker compose down && rm -rf /opt/remnawave-bot                       # удалить (из /opt/remnawave-bot)
```

Параметры `.env`: `PANEL_URL`, `REMNAWAVE_API_TOKEN`, `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID` (можно несколько через запятую), `TZ`, `INTERVAL_SEC`, `ONLINE_WINDOW_SEC`, `NOTIFY_NODES`, `NOTIFY_LIMITS`, `NOTIFY_BILLING`, `NOTIFY_UPDATES`, `QUIET_HOURS` (часы через запятую или диапазон `23-8`), `DND_TIME`, `NOTIFY_USERS`, `NOTIFY_PANEL`, `TELEGRAM_OBSERVERS` (`ID:виды;ID:виды`), `USER_CABINET`, `USER_REMINDERS`, `REMIND_DAYS`, `REMIND_TRAFFIC`, `WEBHOOK_SECRET` (пусто — вебхуки выключены), `WEBHOOK_PORT`, `TELEGRAM_PROXY` (необязательно).

## Настройки

Окно настроек разделено на разделы — меню слева:

| Раздел | Параметры |
|---|---|
| Панель | Адрес панели; API-токен; интервал обновления (секунды, по умолчанию 30); за сколько последних секунд активности пользователь считается онлайн (по умолчанию 300) |
| Telegram-бот | Токен бота, ID чата («привязать чат»), что присылать, время кнопки «не беспокоить», тихие часы по расписанию; «скопировать команду установки» на сервер, «отправить тест» |
| Обновления | Репозиторий `owner/repo`, токен только на чтение, кнопка «проверить обновления» |
| Метрики | Адрес Prometheus `/metrics` и данные Basic Auth; кнопка «сохранить /metrics в файл» сохраняет ответ в `%APPDATA%\RemnawaveMonitor\metrics.txt` для разбора (в интерфейсе эти метрики не отображаются) |
| Общие | Тема (тёмная или светлая); запуск вместе с Windows в свёрнутом виде |

Автозапуск создаёт запись в реестре текущего пользователя (права администратора не нужны) и запускает программу с ключом `--tray`.

## Обновление программы

Программа сама проверяет релизы этого репозитория при запуске и раз в 6 часов.

1. В настройках, раздел «Обновления программы», укажите репозиторий (`owner/repo`) и токен.
2. Если вышла более новая версия, в шапке появляется зелёная плашка «доступна версия X · обновить» и приходит уведомление.
3. По клику программа скачивает релиз, подменяет `RemnawaveMonitor.exe` (старый файл на время переименовывается в `.old` и удаляется при следующем запуске) и перезапускается.

Для приватного репозитория нужен **токен только на чтение**: GitHub → Settings → Developer settings → Fine-grained tokens, доступ только к этому репозиторию, право **Contents: Read-only**. Токен с правом записи в программу вводить не нужно.

Отдельно программа раз в 6 часов смотрит последние релизы самого Remnawave (репозитории `remnawave/backend` и `remnawave/node`) и показывает в шапке жёлтую плашку, если панель или ноды отстают. Версия панели берётся из её API.

## Где хранятся данные и безопасность

Все файлы лежат в `%APPDATA%\RemnawaveMonitor`:

| Файл | Содержимое |
|---|---|
| `settings.json` | Настройки. Токены (панели, Telegram, обновлений) и пароль метрик хранятся **зашифрованными** средствами Windows (DPAPI): расшифровать их можно только в той же учётной записи Windows на том же компьютере |
| `cache.json` | Последние полученные данные: показываются, если панель недоступна |
| `incidents.json` | Журнал событий |
| `metrics.txt` | Сохранённый ответ `/metrics` (появляется только по кнопке в настройках) |

Рекомендации:

- Используйте для панели токен только на чтение.
- Не публикуйте и не отправляйте `settings.json` — при смене компьютера токены придётся ввести заново.
- Токены GitHub делайте с минимальными правами и ограниченным сроком.

## Какие запросы выполняет программа

К панели Remnawave (с Bearer-токеном):

- `GET /api/users` — пользователи;
- `GET /api/nodes` — ноды, их состояние, ресурсы, версии;
- `GET /api/system/nodes/metrics` — трафик по нодам (необязательно);
- `GET /api/infra-billing/nodes` — даты оплаты серверов (необязательно);
- `GET /api/system/metadata` — версия панели (необязательно).

Необязательные запросы при ошибке просто пропускаются.

К внешним сервисам:

- `api.github.com` — релизы этого репозитория (обновление программы) и релизы Remnawave;
- `api.telegram.org` — только кнопки «привязать чат» и «отправить тест» в настройках;
- `1.1.1.1`, `8.8.8.8`, `77.88.8.8` (TCP 443) — проверка, есть ли у компьютера интернет, только когда панель не ответила.

## Сборка и выпуск версий

**Локально** (нужен .NET 8 SDK, Windows):

```
dotnet publish -c Release -r win-x64 --self-contained false -p:PublishSingleFile=true
```

Результат: `bin\Release\net8.0-windows\win-x64\publish\RemnawaveMonitor.exe`. Если сборка ругается на папку `obj`, удалите `bin` и `obj` и повторите.

**Через GitHub Actions** (`.github/workflows/build.yml`):

- каждый push в ветку `main` запускает сборку на `windows-latest`, версия — `1.3.<номер запуска>`;
- при push тега вида `vX.Y.Z` версия берётся из тега;
- в обоих случаях создаётся релиз `vX.Y.Z` с файлом `RemnawaveMonitor-win-x64.zip`;
- параллельно собирается Docker-образ бота `ghcr.io/q3ry777/remnawave-bot` (теги `latest` и номер версии);
- чтобы закоммитить без сборки и релиза, добавьте `[skip ci]` в сообщение коммита.

Версия, под которой собрана программа, показана в шапке окна. Локальная сборка берёт версию из `RemnawaveMonitor.csproj`.

## Ограничения

- Бот работает на том же сервере, что и панель: о падении самого сервера он сообщить не может.
- Названия некоторых полей API Remnawave различаются между версиями панели. Нагрузка, скорость, версии и данные биллинга ищутся по имени поля; если поля нет, соответствующая часть карточки ноды просто не показывается.
- Загрузки процессора в процентах и занятости диска в API панели нет — показываются память, load average и скорость.
