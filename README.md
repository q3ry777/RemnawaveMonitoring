# Remnawave Monitor

Приложение для Windows, которое следит за панелью [Remnawave](https://github.com/remnawave): пользователями, нодами, вашими сайтами, оплатой серверов и версиями. Живёт в системном трее, показывает проблемы красной иконкой и уведомлениями, ведёт журнал событий, умеет присылать тревоги в Telegram и сам обновляется из релизов этого репозитория.

Стек: C#, .NET 8, WPF. Все настройки хранятся локально, токены — в зашифрованном виде.

## Требования

- Windows 10 или 11.
- [.NET 8 Desktop Runtime](https://dotnet.microsoft.com/download/dotnet/8.0), если используется сборка из релизов (она не содержит среду выполнения внутри).
- Доступ к панели Remnawave и её API-токен. Достаточно токена **только на чтение**.

## Установка и первый запуск

1. Скачайте `RemnawaveMonitor-win-x64.zip` из последнего релиза и распакуйте `RemnawaveMonitor.exe` в любую постоянную папку (не в «Загрузки»).
2. Запустите программу и откройте **«настройки»**.
3. Укажите адрес панели и API-токен, при необходимости измените остальные параметры и нажмите **«сохранить»**.
4. Для автоматических обновлений программы заполните раздел «Обновления программы» (см. [ниже](#обновление-программы)).

Запуск второй копии невозможен: она лишь покажет окно уже работающей. При закрытии крестиком окно прячется в трей; полный выход — пункт «Выход» в меню иконки.

## Что показывает программа

Главное окно состоит из трёх вкладок. Сверху — шапка с названием, версией программы, плашками о новых версиях и кнопками «журнал», «тема», «настройки», «обновить». Под ней — счётчики «онлайн» и «ноды N/M». Данные обновляются автоматически (по умолчанию каждые 30 секунд).

### Пользователи

Список всех пользователей панели.

- Имя, статус (ACTIVE и др.), трафик, последняя нода с флагом страны, время последней активности.
- Если у пользователя есть лимит трафика, показывается «использовано / лимит» и полоска расхода: жёлтая от 80%, красная от 95%.
- Рядом с именем появляется метка срока подписки: «ещё N д» за 7 дней, красная за 3 дня, «истёк» после окончания.
- «Онлайн» — пользователь, чья последняя активность была не раньше заданного окна (по умолчанию 300 секунд). Онлайн-пользователи отмечены зелёной точкой со свечением.
- **Поиск** по имени.
- **Сортировка** по клику на заголовок столбца: имя, статус, трафик, нода, активность (повторный клик меняет направление).
- **Фильтры:** «только онлайн» и «проблемные» (не ACTIVE, лимит близок, подписка скоро истекает).
- Меню по правому клику: копировать имя, копировать ссылку подписки, открыть панель в браузере.
- При автообновлении положение прокрутки сохраняется.

### Ноды

Каждая нода — карточка из трёх строк.

1. Точка состояния, флаг, название, статус; трафик ноды («использовано / лимит», `∞` без лимита, полоска при наличии лимита); аптайм Xray; число пользователей онлайн.
2. Шкалы **CPU**, **RAM** и **ДИСК** сервера в процентах, текущая скорость ↓ и ↑. Загрузка CPU и диск берутся [по SSH](#нагрузка-серверов-по-ssh); память — по SSH, а без него — из панели. Без SSH CPU и диск показывают «—». Цвет шкалы: CPU — жёлтый от 70%, красный от 90%; RAM — от 75% и 90%; диск — от 80% и 90%. Подсказки при наведении: число ядер и load average, «занято / всего» для памяти и диска. Если сервер по SSH не отвечает, причина видна отдельной строкой внизу карточки (`ssh: неверный логин или пароль` и т.п.).
3. Доступность и служебная информация (показываются те части, для которых есть данные):
   - **ping и TCP-порт** ноды с вашего компьютера (например, `ping 23 мс · :443 ✓`);
   - **доступность из России**: проверка через check-host.net с российских точек (например, `из РФ 3/3 · 41 мс`);
   - **версии** ноды и Xray, устаревшая нода подсвечена: `node 3.4.0 → 3.4.1`;
   - **оплата сервера** из биллинга панели: `оплата через 5 д (10.10) · провайдер`; жёлтая за 7 дней, красная за 3 дня и при просрочке.

Меню по правому клику: копировать имя, копировать адрес ноды, открыть панель.

### Сервисы

Проверка ваших сайтов. Для каждого адреса из списка в настройках раз в минуту выполняется запрос и показываются:

- код ответа и время ответа;
- срок действия TLS-сертификата («TLS 62 д»): жёлтый за 14 дней, красный за 3 дня, при ошибке или истечении;
- цвет точки: зелёный — ответ 2xx/3xx, жёлтый — 4xx, красный — 5xx, ошибка или таймаут.

Меню по правому клику: копировать адрес, открыть в браузере. Редирект не отслеживается: проверяется именно указанный адрес.

### Прочее в интерфейсе

- **Тёмная и светлая тема.** Переключается кнопкой «тема» или в настройках; цвет системного заголовка окна подстраивается под тему.
- **Плашка «нет связи с панелью»**: если панель недоступна, программа показывает последние сохранённые данные с временем их получения.
- Размер окна запоминается.
- Минимальная ширина окна — 960 пикселей.

## Иконка в трее и уведомления

**Цвет иконки**

- **Зелёная** — непрочитанных проблем нет.
- **Красная** — появилась новая проблема, которую вы ещё не отметили прочитанной.

Проблема считается прочитанной (иконка снова зеленеет), если вы:

- кликнули по уведомлению (откроется журнал событий);
- закрыли уведомление крестиком в течение нескольких секунд после показа;
- нажали «всё прочитано» в журнале или закрыли окно журнала;
- выбрали «Отметить прочитанным» в меню иконки.

Если проблема продолжается, а вы её уже отметили, иконка остаётся зелёной, но в подсказке видно ⚠, а в журнале событие числится как «идёт».

**Подсказка** при наведении: `онлайн 4 · ноды 6/6 · RAM до 49% · сайты 6/6`.

**Меню иконки:** Открыть, Журнал событий, Отметить прочитанным, Настройки, Выход. Двойной клик открывает главное окно.

**О чём приходят уведомления**

- нода не в сети, Xray остановлен;
- нода недоступна с вашего ПК (при том что панель считает её рабочей); если с ПК недоступны все ноды сразу, считается, что проблема у вас, и уведомления нет;
- нода недоступна из России (возможная блокировка);
- потеря связи с панелью;
- сайт недоступен, сертификат истекает;
- срок оплаты сервера (за 3 дня и при просрочке);
- пользователь израсходовал 95% лимита трафика или у него истекает подписка (за 3 дня и после окончания);
- вышли новые версии Remnawave (панель, нода) и самой программы;
- восстановление после проблемы.

**Защита от ложных тревог.** О проблеме сообщается, только если она подтвердилась при двух проверках подряд. Проблемы, которые уже были в момент запуска программы, попадают в журнал как прочитанные и тревогу не поднимают.

## Журнал событий

Окно открывается кнопкой «журнал» в шапке (на ней видно число непрочитанных) или из меню иконки.

- Каждая проблема — строка: время начала, объект, описание, состояние. Активные проблемы показывают «идёт N мин», решённые — «решено · N мин».
- Новые события подсвечены и помечены `NEW`.
- В верхней части — сводка: активно сейчас, новых, всего.
- Кнопки: «всё прочитано», «очистить решённые», «закрыть».
- Журнал хранится в файле и переживает перезапуск; хранятся последние 300 записей. Проблемы, которые были активны на момент закрытия программы, при следующем запуске помечаются завершёнными.

## Telegram

Программа может присылать те же тревоги в Telegram и отвечать на команды. Это работает, **только пока программа запущена** на компьютере.

**Подключение**

1. Создайте бота у [@BotFather](https://t.me/BotFather) (`/newbot`) и скопируйте токен.
2. Напишите боту любое сообщение.
3. В настройках программы, раздел «Telegram»: вставьте токен, нажмите «привязать чат» (программа найдёт номер вашего чата), нажмите «отправить тест», затем «сохранить» и включите галочку «отправлять уведомления в Telegram».

**Что приходит**

- Тревоги и восстановления (с длительностью простоя), например `🔴 Нода … не в сети` и `🟢 Нода … снова в сети (простой 8 мин)`.
- Лимиты и подписки пользователей, оплата серверов, новые версии.
- Для каждого вида есть своя галочка в настройках: ноды и панель; сайты и сертификаты; лимиты и подписки; оплата; новые версии.

**Не беспокоить.** В настройках Telegram можно включить «не присылать уведомления до» и указать время (например, `08:00`). Время берётся с часов компьютера: если оно сегодня уже прошло, режим действует до этого времени завтра. Под полем видно, до какого момента и сколько осталось. Пока режим включён, тревоги в Telegram не отправляются (в журнал событий и в трей они попадают как обычно), а ответы на команды и кнопки бота приходят. Когда время наступает, режим выключается сам.

**Тихие часы по расписанию.** Там же: «тихие часы по расписанию — каждый день» и сетка из 24 часов — нажмите на часы, когда уведомления не нужны (час `23` = с 23:00 до 23:59; есть кнопки «ночь 23–08» и «очистить»). Можно выбрать несколько участков, например ночь и обед. Подсказка под сеткой показывает выбранные интервалы и по часам компьютера — идёт ли тишина сейчас и когда начнётся или закончится. Тихие часы и разовый режим работают вместе.

**Индикатор.** Пока уведомления в Telegram не отправляются, в шапке программы видна плашка `☾ тихо до 08:00`, а `/status` в боте показывает строку `🔕 Не беспокоить до 08:00`.

**Меню и команды.** Под полем ввода всегда доступна клавиатура с кнопками. Те же действия — командами (они же появляются в меню «/»):

| Команда | Что делает |
|---|---|
| `/status` | Сводка: онлайн, ноды, сайты, активные проблемы |
| `/nodes` | Подробности по каждой ноде |
| `/users` | Кто сейчас онлайн и на какой ноде |
| `/problems` | Активные проблемы из журнала |
| `/services` | Статус сайтов и срок сертификатов |
| `/version` | Версии панели, нод и программы |
| `/vpn` | Результат xray-чекера: какие подключения работают из РФ |
| `/help` | Список команд |

Все команды только читают данные и ничего не меняют в панели.

**Прочее**

- Бот отвечает только привязанному чату.
- Если Telegram недоступен, сообщения копятся и отправляются позже; сообщения старше 30 минут отбрасываются.
- Для сетей, где Telegram заблокирован, в настройках можно указать прокси (`http://host:port` или `socks5://host:port`).
- Команда одновременно может обрабатываться только одной программой: не запускайте двух приложений с одним ботом.

## Нагрузка серверов по SSH

Программа раз в минуту заходит на сервер каждой ноды и берёт три показателя: **загрузку CPU**, **занятую память** и **занятость диска** (корневой раздел). Они выводятся шкалами в карточке ноды и в Telegram (`/status`, `/nodes`).

**CPU** — средняя загрузка всех ядер за время между опросами (около минуты), по накопительным счётчикам `/proc/stat`. Первое значение после запуска программы — замер за 2 секунды. Значения меньше 10% показываются с десятыми (`0,8%`). В подсказке при наведении видно, за какой период усреднено.

> Если сервер подключали в версии до 1.3.21, выполните команду установки ещё раз (настройки → серверы · SSH → «скопировать команду установки»; пароль тот же). Со старым скриптом CPU меряется за 1 секунду — на многоядерных серверах при слабой нагрузке такой замер прыгает и часто показывает 0%. Пока скрипт не обновлён, программа усредняет последние 5 замеров, а в подсказке и при проверке подключения напоминает об обновлении.

Вход выполняется под **отдельным пользователем с паролем** (не root). Этот пользователь может только выдать статистику: консоль, другие команды и проброс портов ему запрещены.

**Подключение сервера** (настройки → «серверы · SSH»):

1. Выберите ноду в списке слева (адрес подставляется из панели, порт SSH по умолчанию 22, пользователь `monitor`).
2. Нажмите «сгенерировать» — создастся пароль из 24 символов.
3. Нажмите «скопировать команду установки», вставьте команду в консоль сервера под root и дождитесь строки `RW-MONITOR: готово`.
4. Включите «собирать статистику с этого сервера», нажмите «проверить подключение», затем «сохранить».

**Что делает команда установки:**

- создаёт пользователя (если пользователь с таким именем уже есть и создан не этой командой — останавливается, чтобы не изменить чужую учётную запись);
- задаёт ему пароль;
- ставит скрипт `/usr/local/bin/rw-stats`, который читает `/proc/stat`, `/proc/meminfo` и `df`;
- добавляет в конец `/etc/ssh/sshd_config` блок между метками `# rw-monitor begin` и `# rw-monitor end`: для этого пользователя разрешён вход по паролю, при любом подключении выполняется только `rw-stats` (`ForceCommand`), терминал и проброс портов запрещены. Остальных пользователей, включая root, блок не затрагивает;
- проверяет конфигурацию (`sshd -t`) и перезагружает SSH; если проверка не прошла — возвращает прежний конфиг. Резервная копия: `/etc/ssh/sshd_config.rw-backup`.

Команду можно запускать повторно (например, чтобы сменить пароль) — блок в конфиге заменяется, а не дублируется. Если в `sshd_config` задан `AllowUsers`/`AllowGroups`, команда об этом предупредит: пользователя нужно добавить туда вручную.

**Ключ сервера.** При первом подключении программа запоминает отпечаток ключа сервера (SHA256). Если ключ изменится, сбор остановится с ошибкой «ключ сервера изменился» — это защита от подмены сервера. Если сервер переустанавливали, нажмите «сбросить ключ» в настройках.

**Удаление с сервера:** удалите блок `# rw-monitor begin … # rw-monitor end` из `/etc/ssh/sshd_config`, перезагрузите SSH, затем `userdel -r monitor` и `rm /usr/local/bin/rw-stats /etc/rw-monitor-user`.

## Xray-чекер (проверка VPN из РФ)

Отдельный сервер в РФ по расписанию (по умолчанию раз в 5 минут) подключается к **каждому** подключению из подписки тестового пользователя через Xray — как настоящий клиент — и открывает через него сайт. Это ловит то, что не видно по проверке порта: блокировку протокола или SNI, сломанный inbound, неверные ключи Reality, недоступность конкретного транспорта (TCP, XHTTP, WS/CDN, gRPC).

Для каждого подключения чекер также проверяет, открыт ли его порт из РФ, и подсказывает причину: «порт доступен — похоже на блокировку протокола/SNI или ошибку настройки» или «порт недоступен из этой сети». Поддерживаются VLESS и Trojan (TCP, WS, XHTTP, gRPC, HTTPUpgrade; Reality, TLS). Неподдерживаемые протоколы помечаются отдельно и тревог не вызывают. Информационные «ссылки» панели (срок подписки и т.п.) пропускаются.

**Где видно:**

- в карточке ноды — строка `VPN из РФ: ✓ TCP-Reality 180 мс  ✗ XHTTP` (подключение относится к ноде, если совпадает адрес — в том числе по IP — или в названии есть имя ноды); подробности с ошибками — при наведении;
- в строке над списком — `VPN из РФ 7/8`; при наведении — все подключения, включая не привязанные к нодам (например, CDN);
- в журнале событий, на иконке в трее и в Telegram — тревога, если подключение не работает в двух проверках подряд, и сообщение о восстановлении; `/vpn` в боте и строка в `/status`.

Уведомления в Telegram по-прежнему отправляет программа на компьютере; на сервере работает только проверка.

**Подключение** (настройки → «xray-чекер»):

1. В панели создайте пользователя для проверки (например, `rw-checker`) с доступом ко всем нодам и небольшим лимитом трафика. Впишите его имя — программа найдёт его подписку.
2. Укажите адрес сервера в РФ и порт SSH, нажмите «сгенерировать» (пароль пользователя для чтения результата), затем «скопировать команду установки» и выполните её на сервере под root. Дождитесь `RW-CHECKER: готово` — команда сразу покажет первую проверку.
3. Включите «использовать xray-чекер», нажмите «проверить подключение», затем «сохранить».

**Что делает команда установки:** ставит `curl`, `unzip`, `python3` (apt/dnf/yum); скачивает последний Xray с GitHub в `/usr/local/lib/rw-checker/`; кладёт скрипт проверки `rw-checker.py`; создаёт системного пользователя `rw-checker`, от которого работает проверка; записывает ссылку подписки в `/etc/rw-checker/config.json` (доступна только root и `rw-checker`); создаёт `rw-checker.service` и `rw-checker.timer`; заводит пользователя для чтения результата (по умолчанию `rwcheck`), которому по SSH разрешено только получить `/var/lib/rw-checker/result.json` (ForceCommand, без консоли и проброса портов, блок `# rw-checker begin … end` в `sshd_config`, резервная копия `sshd_config.rw-checker-backup`). Команду можно запускать повторно — например, чтобы сменить пользователя, пароль или интервал; Xray при этом обновится.

**Команды на сервере:**

```
systemctl status rw-checker.timer          # расписание и время следующего запуска
systemctl start rw-checker.service         # проверить прямо сейчас
journalctl -u rw-checker.service -n 50     # журнал проверок
cat /var/lib/rw-checker/result.json        # последний результат
nano /etc/rw-checker/config.json           # ссылка подписки; можно добавить "test_url" и "timeout"
```

**Удаление с сервера:**

```
systemctl disable --now rw-checker.timer
rm -f /etc/systemd/system/rw-checker.service /etc/systemd/system/rw-checker.timer && systemctl daemon-reload
sed -i '/^# rw-checker begin/,/^# rw-checker end/d' /etc/ssh/sshd_config && systemctl reload ssh
userdel -r rwcheck; userdel rw-checker
rm -rf /usr/local/lib/rw-checker /etc/rw-checker /var/lib/rw-checker
```

## Настройки

Окно настроек разделено на разделы — меню слева:

| Раздел | Параметры |
|---|---|
| Панель | Адрес панели; API-токен; интервал обновления (секунды, по умолчанию 30); за сколько последних секунд активности пользователь считается онлайн (по умолчанию 300) |
| Серверы · SSH | Для каждой ноды: включение сбора, адрес и порт SSH, пользователь, пароль; кнопки «сгенерировать», «скопировать команду установки», «проверить подключение», «сбросить ключ» |
| Xray-чекер | Включение; тестовый пользователь панели; интервал проверки; адрес и порт SSH сервера в РФ, пользователь и пароль для чтения результата; кнопки «сгенерировать», «скопировать команду установки», «проверить подключение», «сбросить ключ» |
| Проверки нод | Ping и TCP-проверка с ПК; проверка из России через check-host.net (раз в 10 минут); порт проверки (по умолчанию 443, `0` — только ping) |
| Сайты | Список адресов для вкладки «Сервисы», по одному в строке |
| Telegram | Включение, токен бота, ID чата, прокси, виды сообщений, «не беспокоить до» (время по часам компьютера), тихие часы по расписанию (выбор часов), тестовое сообщение |
| Обновления | Репозиторий `owner/repo`, токен только на чтение, кнопка «проверить обновления» |
| Метрики | Адрес Prometheus `/metrics` и данные Basic Auth; кнопка «сохранить /metrics в файл» сохраняет ответ в `%APPDATA%\RemnawaveMonitor\metrics.txt` для разбора (в интерфейсе эти метрики не отображаются) |
| Общие | Тема (тёмная или светлая); запуск вместе с Windows в свёрнутом виде |

Автозапуск создаёт запись в реестре текущего пользователя (права администратора не нужны) и запускает программу с ключом `--tray`.

## Обновление программы

Программа сама проверяет релизы этого репозитория при запуске и раз в 6 часов.

1. В настройках, раздел «Обновления программы», укажите репозиторий (`owner/repo`) и токен.
2. Если вышла более новая версия, в шапке появляется зелёная плашка «доступна версия X · обновить» и приходит уведомление.
3. По клику программа скачивает релиз, подменяет `RemnawaveMonitor.exe` (старый файл на время переименовывается в `.old` и удаляется при следующем запуске) и перезапускается.

Для приватного репозитория нужен **токен только на чтение**: GitHub → Settings → Developer settings → Fine-grained tokens, доступ только к этому репозиторию, право **Contents: Read-only**. Токен с правом записи в программу вводить не нужно.

Отдельно программа раз в 6 часов смотрит последние релизы самого Remnawave (репозитории `remnawave/backend` и `remnawave/node`) и показывает в шапке жёлтую плашку, если панель или ноды отстают. Версия панели берётся из её API.

## Где хранятся данные и безопасность

Все файлы лежат в `%APPDATA%\RemnawaveMonitor`:

| Файл | Содержимое |
|---|---|
| `settings.json` | Настройки. Токены (панели, Telegram, обновлений), пароли SSH и пароль метрик хранятся **зашифрованными** средствами Windows (DPAPI): расшифровать их можно только в той же учётной записи Windows на том же компьютере |
| `cache.json` | Последние полученные данные: показываются, если панель недоступна |
| `incidents.json` | Журнал событий |
| `metrics.txt` | Сохранённый ответ `/metrics` (появляется только по кнопке в настройках) |

Рекомендации:

- Используйте для панели токен только на чтение.
- Не публикуйте и не отправляйте `settings.json` — при смене компьютера токены придётся ввести заново.
- Токены GitHub делайте с минимальными правами и ограниченным сроком.

## Какие запросы выполняет программа

К панели Remnawave (с Bearer-токеном):

- `GET /api/users` — пользователи;
- `GET /api/nodes` — ноды, их состояние, ресурсы, версии;
- `GET /api/system/nodes/metrics` — трафик по нодам (необязательно);
- `GET /api/infra-billing/nodes` — даты оплаты серверов (необязательно);
- `GET /api/system/metadata` — версия панели (необязательно).

Необязательные запросы при ошибке просто пропускаются.

К внешним сервисам:

- `api.github.com` — релизы этого репозитория (обновление программы) и релизы Remnawave;
- `check-host.net` — проверка доступности нод из России (можно отключить в настройках; на сервис отправляются адрес и порт ноды);
- `api.telegram.org` — Telegram (только если включён);
- ваши сайты из списка — проверка доступности и сертификатов;
- сами ноды — ping и TCP-соединение с порта проверки;
- серверы нод по SSH — сбор CPU, памяти и диска (только для включённых в настройках).

## Сборка и выпуск версий

**Локально** (нужен .NET 8 SDK, Windows):

```
dotnet publish -c Release -r win-x64 --self-contained false -p:PublishSingleFile=true
```

Результат: `bin\Release\net8.0-windows\win-x64\publish\RemnawaveMonitor.exe`. Если сборка ругается на папку `obj`, удалите `bin` и `obj` и повторите.

**Через GitHub Actions** (`.github/workflows/build.yml`):

- каждый push в ветку `main` запускает сборку на `windows-latest`, версия — `1.3.<номер запуска>`;
- при push тега вида `vX.Y.Z` версия берётся из тега;
- в обоих случаях создаётся релиз `vX.Y.Z` с файлом `RemnawaveMonitor-win-x64.zip`;
- чтобы закоммитить без сборки и релиза, добавьте `[skip ci]` в сообщение коммита.

Версия, под которой собрана программа, показана в шапке окна. Локальная сборка берёт версию из `RemnawaveMonitor.csproj`.

## Ограничения

- Telegram-уведомления и команды работают только при запущенной программе. Когда компьютер выключен или спит, тревог не будет.
- Названия некоторых полей API Remnawave различаются между версиями панели. Нагрузка, скорость, версии и данные биллинга ищутся по имени поля; если поля нет, соответствующая часть карточки ноды просто не показывается.
- Проверка «из России» проверяет доступность TCP-порта. Блокировка по протоколу или SNI при открытом порте таким способом не обнаруживается.
- Загрузки процессора в процентах и занятости диска нет ни в API, ни в метриках панели — они доступны только при подключении сервера по SSH.
- SSH-порт серверов должен быть доступен с вашего компьютера.
